# Journal Cover Letter Skill — Product Specification v1.0

## 1. Locked product decisions

- **Runtime target:** Portable Agent Skill compatible with Codex and ChatGPT surfaces that support the Agent Skills format.
- **Domain scope:** Medicine and life sciences first, while remaining usable for other academic disciplines.
- **Human-control gate:** Mandatory user confirmation after manuscript fact extraction and contribution ranking.
- **Previous-letter handling:** Always ask whether a prior cover letter exists and how it may be used: format only; format and tone; maximum wording preservation; or fact checking only.
- **Default deliverables:** Final text, submission-ready DOCX, concise factual/journal-compliance audit, and remaining author-confirmation items.

## 2. Product objective

Convert manuscript files and current journal evidence into a reliable editor-facing cover letter. The system must not merely summarize the manuscript. It must identify the evidence hierarchy, rank genuine contributions, research current journal requirements, learn an authorized prior-letter format, and iteratively compress the first draft into an editorial screening brief.

## 3. Core user journey

1. User uploads manuscript-related files.
2. Skill identifies file roles and extracts a manuscript fact sheet.
3. Skill proposes a ranked contribution hierarchy.
4. Skill stops for user confirmation.
5. User confirms facts, names the target journal and article type, and optionally uploads a previous cover letter.
6. Skill researches current official journal requirements, readership, scope, editorial information, special routes, and recent related content.
7. Skill produces an evidence-grounded first draft.
8. Skill performs the expert-informed editorial iteration.
9. Skill runs five audits.
10. Skill outputs final text, DOCX, audit summary, and unresolved confirmation items.

## 4. Expert-informed editorial iteration

Use the default `1-5-1-1` architecture:

- **1 central question:** Align the cover letter with the manuscript title and core decision problem.
- **Up to 5 ranked contributions:** Evidence base; taxonomy/theory; concept/insight; framework/tool; practice boundary.
- **1 positive/negative evidence boundary:** State what the evidence supports and what it does not support.
- **1 declarations block:** Keep required submission declarations together.

Apply four content operations:

- **Merge:** absorb eligibility boundaries, quality appraisal, and secondary analyses into stronger contributions.
- **Demote:** treat writing structure, claim-first presentation, and routine reporting choices as supporting details rather than independent contributions.
- **Delete:** remove generic journal praise, duplicated fit statements, obsolete prior-submission language, and low-value process details.
- **Reorder:** present credibility before novelty, novelty before framework, and framework before practice boundary.

## 5. Five audit gates

1. **Fact audit:** Exact title, authors, article type, design, counts, dates, registration identifiers, results, and declarations.
2. **Journal audit:** Current scope, article type, readership, cover-letter rules, salutation, and special pathway.
3. **Contribution audit:** Hierarchy, independence, redundancy, and decision relevance.
4. **Claim-strength audit:** Causality, generalizability, validity, implementation readiness, and unsupported superlatives.
5. **Editorial-read audit:** The problem, credibility, novelty, fit, and evidence boundary must be clear within 30–45 seconds.

## 6. Source policy

Priority order:

1. official journal instructions for authors;
2. official aims and scope;
3. official article-type guidance;
4. official editorial-team page;
5. official publisher policy pages;
6. recent relevant content published by the journal;
7. recognized secondary sources only for noncritical gaps;
8. third-party summaries only as labeled fallbacks.

Internally label each journal-related finding as an explicit requirement, explicit scope statement, observed publication pattern, editorial inference, or unverified claim. Never call an inferred pattern an official preference.

## 7. Submission branches

Support:

- initial submission;
- revised/resubmitted manuscript to the same journal;
- transfer or special prior-review pathway;
- new submission to a different journal after rejection, withdrawal, or non-transfer.

The system must not reuse resubmission language for a new journal.

## 9. Current MVP boundaries

The MVP can:

- analyze manuscript and title-page content;
- research a target journal using available web tools;
- rank and confirm contributions;
- analyze a prior cover letter;
- draft and iteratively rewrite the letter;
- run deterministic text checks;
- generate a DOCX and inherit basic page/font settings from a reference DOCX.

The MVP does not yet include:

- a persistent journal-policy database;
- a graphical multi-step wizard;
- automated submission-system entry;
- a full visual diff engine for arbitrary legacy DOCX styles;
- public plugin packaging, authentication, analytics, or hosted storage.

These belong to the later Plugin/App phase.
