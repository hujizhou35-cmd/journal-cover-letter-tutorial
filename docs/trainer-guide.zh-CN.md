# 傻瓜式教程：用 Trainer 改进 Skill

当你拥有“当前投稿信 Skill＋稿件＋有权分析的专家投稿信”时，可以使用 Trainer。

## 需要准备什么？

1. 当前 `.skill` 文件或 Skill 文件夹。
2. 手稿及理解论文所需的其他材料。
3. 想要强化的路线：Research、Review、Bibliometrics，或者准备新增的路线。
4. 专家投稿信——第一次生成前不要把它发给生成者。
5. 明确同意把专家信作为匿名比较材料。

## 最简单的操作流程

1. 新建一个干净对话，只提供 Trainer、当前 Skill 和稿件材料。
2. 要求生成基线投稿信，不要提到或上传专家信。
3. 保存并封存这次输出。
4. 把专家信交给负责比较的对话，并授权匿名分析。
5. 查看双方差异和建议修改的通用规则。
6. 再新建一个干净对话，只提供修改后的 Skill 和稿件材料。
7. 把新结果交回比较对话。
8. 重复以上过程，直到改进稳定，或者 Trainer 给出停止原因。

## 什么情况才算真正盲测？

- **最强隔离：**使用不同智能体或 API 上下文，由系统控制输入。
- **实用盲测：**每一轮生成都新建临时对话，记忆和共享项目文件无法提供专家材料。
- **只保护第一次生成：**在同一个对话中延迟上传专家信；专家信揭示后的后续生成不能再称为盲测。
- **已经污染：**生成者已经看过专家信或包含其核心内容的总结。

Trainer 必须如实说明实际采用了哪一种情况。

## 哪些内容不能公开上传？

不要把真实稿件、真实投稿信、作者联系方式、投稿编号、私人期刊来信、对话分享链接或可识别文件名提交到 GitHub。原始案例应保存在被 Git 忽略的私人目录中。

一个案例可以帮助发现问题，但不能证明新版适用于所有论文。
